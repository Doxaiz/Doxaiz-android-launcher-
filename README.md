# Doxaiz launcher

Лаунчер для Android (`com.doxaiz.launcher`), версия 6.0-test. Русский интерфейс, рабочий стол, каталог приложений, пользовательская шторка и резервное копирование.

**Статус:** тестовая версия. Проверено в CI на эмуляторе Android 14 (API 34): сборка, установка, роль HOME, отрисовка рабочего стола и каталога, отсутствие падений. Плавность и аппаратные функции на реальном телефоне не измерялись — эмулятор рисует программно, его метрики кадров для этого непригодны. Светлая тема не завершена: шторка остаётся тёмной. Пользовательские резервные копии JSON не шифруются: по умолчанию сохраняется только раскладка, скрытые приложения попадают в файл лишь при явном выборе «Полная копия».

## Скачать

Тестовая сборка: [v6.0-test](https://github.com/Doxaiz/Doxaiz-android-launcher-/releases/tag/v6.0-test).
APK подписан отладочным ключом CI — он не обновит уже установленную версию, для
этого нужна сборка своим ключом через `build.sh`.

## Сборка

Проект собирается штатным Gradle: `./gradlew assembleDebug` (Android SDK Platform 34, AGP 8.2.2, Gradle wrapper 8.7, JDK 17). Для проверки правил R8: `./gradlew assembleRelease`. Приложение не запрашивает разрешение INTERNET; сеть нужна только для загрузки инструментов сборки. Замер скорости и работа с интернетом — отдельное приложение [Net Optimizer](https://github.com/Doxaiz/net-optimizer-by_doxaiz), см. `AUDIT.md` §29.5.

Для сборки подписанного APK через `build.sh` требуются JDK, Android SDK Platform 34 и Build Tools 34 (скрипт ожидает их в `platforms/android-34` и `build-tools/android-14` внутри `ANDROID_SDK_ROOT`), bash и zip. Передайте путь к приватному хранилищу ключей через `DOXAIZ_KEYSTORE`, пароль хранилища через `DOXAIZ_KEYSTORE_PASSWORD`, пароль ключа через `DOXAIZ_KEY_PASSWORD`, при необходимости алиас через `DOXAIZ_KEY_ALIAS` (по умолчанию `doxaiz`). Затем выполните `bash build.sh`. Скрипт не генерирует ключ и не содержит пароль.

**Не публикуйте хранилище ключей и пароли.** Для обновления уже установленного APK необходим совместимый ключ подписи; APK, подписанный новым независимым ключом, не установится как обычное обновление. Сохраните оригинальный ключ отдельно. Debug APK использует другую подпись и тоже не обновит установленную release-версию.

## Обои

Встроенное изображение — сгенерированная композиция по мотивам Kurumi и Xiao Bai, не официальный кадр. Права на персонажей принадлежат их правообладателям; перед публичным распространением изображение следует проверить на соответствие применимым правам.

## Что изменилось в 6.0

* **Старт не ждёт чужую оболочку.** Перенос раскладки со штатного рабочего стола
  читал базу другого приложения в главном потоке и повторялся на каждом старте с
  пустым столом. Теперь рабочий стол показывается сразу, а перенос пробуется в
  фоне и один раз.
* **Иконки не теряются.** При переполнении всех страниц две иконки могли получить
  одну клетку — нажималась только первая. Теперь у каждой своя координата.
* **Нет дублей.** Приложение из «Всех приложений» больше не добавляется на стол
  второй раз, если оно уже там (в том числе в папке).
* **Меньше памяти и подвисаний.** Иконки из дискового кэша уменьшаются при
  чтении; очистка ОЗУ в «Недавних» идёт в фоне; утечка узлов службы доступности
  устранена.
* **Доступность.** Иконки и папки рабочего стола получили текстовые подписи для
  TalkBack.
* **Чистая установка больше не даёт пустой стол.** Раньше первая же пустая
  раскладка считалась готовой (`pages=[[]]`) и сохранялась — авто-раскладка не
  строилась никогда, хотя приложения были видны. Теперь «раскладка построена» —
  это отдельный сохраняемый признак, а ручной пустой стол не перезаполняется.
* **Поиск в каталоге дешевле.** Оценка совпадения считается один раз на
  приложение, а не дважды на каждое сравнение при сортировке; при задержке
  клавиатуры следующий пересчёт идёт без дополнительной паузы. Полный пересчёт
  списка — 10 мс медиана (замер самого приложения, см. `AUDIT.md` §19).
* **Контраст палитры, а не только обоев.** Отдельный разбор четырёх палитр
  `GlassTheme` на те же пороги WCAG нашёл то, что не видно «на глаз»: подсказки
  в тёмной теме давали 2,6:1 (это самый мелкий текст в приложении), подпись
  активного чипа — 3,4:1, красное «Удалить приложение» на карточке — 4,1:1.
  Значения заменены по расчёту с сохранением оттенка, а `tests/ContrastTest.java`
  теперь считает настоящую палитру (4 стиля × 3 уровня непрозрачности) и упал бы
  на прежних цветах. Разбор — `AUDIT.md` §22.
* **Читаемость на любых обоях.** Подписи иконок и дока больше не белый текст
  «в воздухе»: под ними подложка, плотность которой вычисляется по контрасту
  WCAG для худшего случая (белые обои). Скрим рабочего стола теперь рисуется и
  при системных обоях — раньше слой в этом режиме просто скрывался.
* **Прокрутка каталога не ждёт иконок.** Пока список движется, показываются уже
  готовые иконки, а декодирование с диска не запускается; по остановке
  недостающие иконки дорисовываются. Так кадр прокрутки не тратится на
  распаковку WEBP.
* **Подтверждение PIN больше не выполняет чужое действие.** На Android 8–10
  проверка уходит в системный экран PIN, и отложенное действие жило в одном поле
  активности: отмена оставляла его висеть, а следующий запрос мог выполнить
  предыдущий — подтвердив PIN для скрытых приложений, можно было получить запуск
  экспорта защищённой копии. Теперь пара «успех/отмена» принадлежит самой
  проверке и срабатывает ровно один раз (`PendingAuthAction`, покрыт тестами).
* **Аварийный экран не зацикливается.** «Попробовать снова» на нём снова
  открывал его же, если стол не строился: отметка сбоя ещё была свежей. Теперь
  экран показывается один раз за запуск, и кнопка действительно пробует.
* **Уголки стилей вернулись.** Параметр `ornamentsEnabled` игнорировался, а
  внутри стояло `false` — свитки Дунхуа и HUD-скобы не рисовались никогда, как и
  настройка «аниме-орнаменты». Теперь запрос уважается (у графита уголков нет по
  определению).
* **Импорт не падает на чужой базе.** Раскладка читалась из `ContentProvider`
  другой оболочки до конца и без ограничения длины строк: битая база или чужой
  провайдер с тем же именем authority давал сотни тысяч строк — OOM в фоновом
  потоке. Теперь предел 2000 строк и обрезка строк на входе, причём тест
  проверяет, что настоящая раскладка под предел не попадает.
* **Учёт трафика заработал.** Суточный и месячный расход считался методом,
  который не вызывался ниоткуда. Учёт перенесён в панель сети (без лишних IPC,
  запись на диск не чаще раза в час), а числа видны в настройках сети.
* **Меньше мусора в настройках.** Набор «скрытых из Недавних» рос без предела —
  каждый свайп по карточке дописывал пакет навсегда. Теперь 200 самых свежих
  записей. Удалены методы-настройки, которые ни разу не вызывались.

Подробности и честные ограничения — в заметках к релизу и `AUDIT.md` §16–§23.

## Если служба не включается: «Настройки с ограниченным доступом»

APK из этого релиза ставится вручную, а Android 13 и новее **запрещает
приложениям из APK включать специальные возможности** — при попытке система
показывает диалог «Настройки с ограниченным доступом: в целях безопасности
доступ к этой функции пока ограничен». Это штатное поведение Android
([разбор в блоге «Лаборатории Касперского»](https://www.kaspersky.ru/blog/restricted-settings-android/25767/)),
а не ошибка Doxaiz и не особенность прошивки.

Ограничение снимается **не в списке специальных возможностей**, а в настройках
самого приложения:

1. **Настройки → Приложения → Все приложения → Doxaiz**
   (на части прошивок: Настройки → Приложения → Doxaiz).
2. Внизу экрана — переключатель **«Разрешить ограниченные настройки»**.
   На прошивках, где его нет внизу, он находится в меню из трёх точек в правом
   верхнем углу («Разрешить запрещённые настройки» / «Предоставить все
   разрешения»). Подтвердите PIN или отпечатком, если спросит.
3. Теперь **Настройки → Специальные возможности → Doxaiz — Панель ОЗУ и
   блокировка → включить**. Переключатель станет активным.

В приложении этот же путь открывается кнопками: «Настройки Doxaiz» →
«Готовность системы» → строка «Настройки с ограниченным доступом» (или пункт
«Служба не включается?»). Первая кнопка ведёт прямо на экран снятия
ограничения, вторая — в спецвозможности.

Зачем это нужно: служба даёт панель ОЗУ и мусорку в недавних, блокировку экрана
двойным касанием, снимок экрана и открытие системной шторки. Без неё лаунчер
работает, но эти функции недоступны.

## Релизы: один и тот же, без новых тегов

В проекте **ровно один** релиз — `doxaiz-test`. Он не пересоздаётся на каждую
итерацию: CI на каждом успешном запуске в `main` перезаписывает в нём APK
(`gh release upload --clobber`) и текст заметок из `RELEASE_NOTES.md`
(`gh release edit`). Новых релизов и новых тегов CI не создаёт — если релиза
нет, шаг просто пропускается.

Так «последняя проверенная сборка» всегда лежит по одной и той же ссылке, а
история версий не превращается в свалку тегов. Заметки к релизу правятся в
`RELEASE_NOTES.md`, а не в интерфейсе GitHub: иначе следующая публикация их
перезапишет.

## Проверка

`./gradlew test` запускает JVM-проверки из `tests/` (расчёты, валидация, кривая перелистывания). Они не заменяют проверку UI, аппаратных возможностей и службы специальных возможностей на реальном устройстве.

### Аварийный возврат на штатный лаунчер

Лаунчер — это HOME-приложение: если он упадёт при старте, рабочий стол не
появится ни по кнопке «Домой», ни после перезапуска. Поэтому на такой случай
есть страховка:

* первый сбой подряд → **аварийный экран** с причиной из журнала диагностики и
  четырьмя выходами (вернуться на штатный лаунчер, попробовать снова, сбросить
  счётчик сбоев, открыть настройки приложения); автоматически ничего не меняется;
* второй сбой подряд → лаунчер сам открывает системный рабочий стол (или
  системный выбор лаунчера);
* успешный запуск сбрасывает счётчик; выгрузка приложения системой падением не
  считается.

Отключить можно в настройках: «Система и быстродействие» → «Аварийный возврат».
Состояние (сколько сбоев подряд, куда переключались) видно в «Диагностике».

Ограничение платформы: Android не позволяет приложению «нажать Домой» за
пользователя, поэтому кнопки — основной путь, автоматика — страховка.
Подробности — `AUDIT.md` §15.

### Журнал диагностики

Настройки → «Система и быстродействие» → **Диагностика**: журнал сбоев, которые
лаунчер переживает молча (иконка не записалась в кэш, копия не прочиталась,
раскладка не сохранилась). Записываются только компонент, тип исключения и
короткое сообщение без путей к файлам; журнал хранит последние 40 записей и
переживает перезапуск. Экран нужен в первую очередь для проверки на реальном
телефоне: если что-то не работает без видимой причины, причина будет здесь.
Подробности — `AUDIT.md` §14.

Android Lint входит в CI с порогом «ошибки валят сборку» (0 ошибок на 6.0-test). Отчёт — `AUDIT.md` §13.

GitHub Actions (`.github/workflows/ci.yml`) дополнительно собирает APK и запускает его на эмуляторе Android 14: установка, назначение HOME, дамп дерева интерфейса, открытие каталога, прокрутка, `dumpsys gfxinfo`, поиск падений именно `com.doxaiz.launcher`. Debug-APK подписывается одноразовым debug-ключом CI — он не подходит для обновления установленной release-версии.

Отчёт по аудиту и журнал правок — в [AUDIT.md](AUDIT.md). Сплошная проверка
на дефекты (гонки, утечки, жизненный цикл, подтверждения, обработка ошибок,
манифест) — §23: пять исправленных дефектов и список того, что проверено и
осталось без изменений.
